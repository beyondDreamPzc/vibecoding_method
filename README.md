# AI Vibe Coding 通用项目开发实操手册

这是一套面向 AI Coding Agent 的通用项目研发提示词与标准作业流程（SOP），适用于 Codex、Claude Code、Cursor 等能够读写代码仓库的工具。

## 文档组成

本仓库由三份文档组成，分别承担不同职责：

| 文档 | 作用 | 使用方式 |
| --- | --- | --- |
| [manual.md](./manual.md) | 实操手册：项目初始化方法、阶段 0～6 提示词、报告模板与核对清单 | 随手册保存，按阶段复制到聊天框 |
| [AGENTS.md](./AGENTS.md) | Codex 使用的长期项目规则 | 复制到目标项目根目录，由 Codex 自动加载 |
| [CLAUDE.md](./CLAUDE.md) | Claude Code 使用的长期项目规则（内容与 AGENTS.md 保持一致） | 复制到目标项目根目录，由 Claude Code 自动加载 |

**规则文件与阶段提示词分开**：长期约束写入 `AGENTS.md` / `CLAUDE.md`，一次只发一个阶段的提示词，不要把整本手册塞进规则文件。

## 适用场景

- 从零创建软件项目
- 在已有项目上继续迭代
- 开发 AI Agent 或 RAG 应用
- 开发普通 Web、API 或移动端系统
- 为团队建立可复用、可验证的 AI 辅助研发流程

## 推荐使用方式

### 第一次创建项目

1. 新建项目目录，并创建 `requirements/`（放业务资料）和 `docs/`（放分析产物）。
2. 把长期规则放到项目根目录：用 Codex 放 `AGENTS.md`；用 Claude Code 放 `CLAUDE.md`；两个工具都用则两个都放。
3. 打开 [manual.md](./manual.md)，按“具体操作：首次开新项目”的步骤执行。
4. 复制“阶段 0”提示词，填写顶部的项目变量后发送；AI 会保存 `docs/project-config.md` 和 `docs/00-project-context.md`。
5. 确认项目理解无误后，再按阶段 1 → 6 逐段复制提示词，每个阶段的产出经人工确认后再进入下一阶段。

### 开发过程中

每次只复制当前阶段的提示词，不要同时发送多个阶段。每阶段结束时要求 AI 按统一报告模板交付文档、验证命令和实际证据，避免未经确认就跳过关键决策或宣称完成。

### 开发下一个模块

不需要重新开始整个项目流程。使用“阶段 6：基于已有底座扩展下一个模块”，在复用现有架构、接口和公共能力的基础上进行增量开发。

## 工作流程

| 阶段 | 内容 | 人工确认点 |
| --- | --- | --- |
| 0 | 项目变量、初始化配置与项目理解 | 确认项目理解与配置 |
| 1 | 业务痛点挖掘和功能选择 | 选择要做的功能 |
| 2 | MVP 需求文档（PRD） | 批准 MVP 范围 |
| 3 | 技术设计与开发计划 | 批准架构与任务卡 |
| 4 | 按任务卡开发、验证和审查 | 各批测试通过 |
| 5 | MVP 独立运行及交付验收 | 确认交付 |
| 6 | 基于已有底座扩展下一个模块 | 确认增量设计 |

## 核心原则

- 先读资料和代码，再设计与开发。
- 区分已确认事实、合理假设和待确认问题。
- 以最小可运行、可演示、可测试的业务闭环为目标。
- 重要需求和架构决策由人工确认，局部实现细节由 AI 自主处理。
- 每批改动都要经过测试、自检和代码审查，并报告真实结果。
- 优先复用已有能力，避免无必要的复杂架构和无关重构。
- 文档、接口、数据库、代码和测试保持一致。
