# AI Vibe Coding 通用项目开发提示词手册

这是一套面向 AI Coding Agent 的通用项目研发提示词与标准作业流程（SOP），适用于 Codex、Claude Code、Cursor 等能够读写代码仓库的工具。

完整手册请查看：[vibecoding.md](./vibecoding.md)

## 适用场景

- 从零创建软件项目
- 在已有项目上继续迭代
- 开发 AI Agent 或 RAG 应用
- 开发普通 Web、API 或移动端系统
- 为团队建立可复用、可验证的 AI 辅助研发流程

## 推荐使用方式

### 第一次创建项目

1. 将 `vibecoding.md` 放入项目目录。
2. 填写文档中的项目变量，包括项目名称、业务资料、仓库位置、技术栈、交付范围和约束等。
3. 复制文档中的“一键启动整个流程”提示词并交给 AI Coding Agent。
4. 按阶段确认需求、架构和开发计划，再进入实现与验收。

### 开发过程中

直接复制 `vibecoding.md` 中对应阶段的提示词，让 AI 执行当前任务。每一阶段都要求提供文档、验证命令和实际证据，避免未经确认就跳过关键决策或宣称完成。

### 开发下一个模块

不需要重新开始整个项目流程。直接使用“阶段 6：基于已有底座扩展下一个模块”，在复用现有架构、接口和公共能力的基础上进行增量开发。

## 工作流程

| 阶段 | 内容 |
| --- | --- |
| 0 | 项目理解和现状审计 |
| 1 | 业务痛点挖掘和功能选择 |
| 2 | MVP 需求文档（PRD） |
| 3 | 技术设计与开发计划 |
| 4 | 按任务卡开发、验证和审查 |
| 5 | MVP 独立运行及交付验收 |
| 6 | 基于已有底座扩展下一个模块 |

## 核心原则

- 先读资料和代码，再设计与开发。
- 区分已确认事实、合理假设和待确认问题。
- 以最小可运行、可演示、可测试的业务闭环为目标。
- 重要需求和架构决策由人工确认，局部实现细节由 AI 自主处理。
- 每批改动都要经过测试、自检和代码审查，并报告真实结果。
- 优先复用已有能力，避免无必要的复杂架构和无关重构。
- 文档、接口、数据库、代码和测试保持一致。
